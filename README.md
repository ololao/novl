# NOVL — анти-DPI транспортный протокол (v0.2)

Сетевой транспортный протокол и библиотека на Rust для передачи трафика через
каналы с глубоким анализом пакетов (L7 DPI / ТСПУ) и защитой от активного
сетевого зондирования. Позиционируется как маскировка под обычный HTTPS-трафик
с полным криптографическим стеком поверх одного общего секрета (PSK).

> **Статус: v0.2.0 — экспериментальный, в активной разработке.**
> Криптография спроектирована самостоятельно, без внешнего аудита. Не
> используйте для защиты данных, потеря которых недопустима.

---

## Протокол v0.2 — что изменилось

| Свойство | v0.1 | v0.2 |
|---|---|---|
| Forward secrecy (PFS) | нет | эфемерный X25519 на каждое соединение |
| Аутентификация сервера | нет | proof в ServerHello, проверка до отправки данных |
| Формат кадров после хендшейка | `len‖pad‖ct` (сигнатура) | TLS-записи `0x17 0x03 0x03` + паддинг до 64 Б |
| Anti-DPI фрагментация | фиксированный split | рандомизация позиции/задержки на соединение |
| Downgrade-защита | нет | версия зашита в MAC токена |
| Подбор MAC | без ограничений | rate-limit 60 неудач/мин на IP |
| Совместимость | — | v0.1.x клиенты поддерживаются сервером v0.2 |

## Архитектура

* **Маскировка транспорта**
  * `TlsChameleon` — генерация TLS 1.3 ClientHello с профилем Chrome
    (порядок шифров, GREASE, ALPN, честный X25519 в key_share). Токен
    аутентификации передаётся в поле `session_id`.
  * `HttpUpgrade` — маскировка под HTTP/1.1 WebSocket Upgrade.
* **Desync-фрагментация** — первый пакет делится на сегменты с рандомной
  позицией и джиттером 0–25 мс; опциональный разрез внутри SNI.
* **Перенаправление зондов** — неаутентифицированный трафик прозрачно уходит
  на fallback-вебсервер через `splice(2)` без копирования в userspace.
* **Anti-replay** — 32 шардированных фильтра со скользящим окном (TTL 90–120 с).
* **UDP-over-TCP** — DNS, VoIP и прочий UDP внутри аутентифицированного
  TCP-потока (ChaCha20-Poly1305).
* **C-ABI** (`libnovl.so` / `libnovl.a`, заголовок `include/novl.h`) — для
  интеграции в Android `VpnService`, iOS и сторонние клиенты.

## Криптографический стек

* **Деривация**: BLAKE3-KDF (контексты `NOVL-v2-SESSION-KEYS`, `NOVL-v2-PROOF`).
* **Хендшейк-токен**: timestamp (8 Б) + соль (8 Б) + BLAKE3-MAC (16 Б),
  MAC связывает версию протокола и публичный ключ клиента.
* **Обмен ключами**: X25519 (эфемерный, клиент и сервер).
* **Транспорт**: ChaCha20-Poly1305, инкрементальный nonce, AAD на заголовок
  кадра, отдельные ключи для каждого направления.

## Ограничения (честно)

* **Нет внешнего аудита.** Схема вдохновлена Noise/REALITY/SS-2022, но это не
  заменяет формальную верификацию.
* **Один PSK на всех** — компрометация клиентского устройства раскрывает общий
  секрет сервера (обратимого Past-трафика это больше не касается, но Future-
  сессии скомпрометированы до ротации ключа).
* **TCP-only транспорт** — head-of-line blocking при потерях; UDP-игры через
  UoT чувствительны к джиттеру.
* Фингерпринт ClientHello воспроизводит Chrome, но не проходит
  tlsfingerprint.io побайтово; TLS-in-TLS статистика длин пакетов остаётся
  вектором детекции (см. Xue et al. 2024).

## Сборка

Требования: Rust 1.77+.

```bash
cargo build --release
cargo test          # 31 unit + 7 integration
```

Артефакты (`target/release/`): `novl-server`, `novl-client`, `libnovl.so`,
`libnovl.a`.

Кросс-компиляция Android (aarch64):

```bash
cargo build --release --target aarch64-linux-android --lib
```

## Запуск

Сервер:

```bash
novl-server --listen 0.0.0.0:7443 --fallback 127.0.0.1:8080 --secret "SECRET"
```

Клиент (локальный SOCKS5):

```bash
novl-client --socks5 127.0.0.1:10800 --server SERVER_IP:7443 \
    --sni addons.mozilla.org --mode tls --secret "SECRET"
```

Параметры клиента: `--split-pos`, `--split-delay` игнорируются в v0.2
(профиль рандомизируется автоматически), `--mode tls|http`.

## Репозитории

* `novl` — протокол, сервер, клиент, C-ABI (этот репозиторий).
* `novl-Android` — форк WireGuard-клиента под Android с движком NOVL
  (ветки `main` + `develop`, релизы и OTA-обновления через GitHub Releases).
